# Cloud Run スペック設定

複数ユーザーの同時利用に対応するため、Cloud Run のリソースとスケーリング設定を増強しました。

## 本番環境 (main ブランチ)

### メインアプリケーション (`izatabi-app`)
- **CPU**: 2 vCPU
- **メモリ**: 4Gi
- **最小インスタンス**: 2（コールドスタート削減）
- **最大インスタンス**: 20（高負荷対応）
- **同時リクエスト数**: 200/インスタンス
- **タイムアウト**: 900秒（AI処理対応）
- **実行環境**: gen2（パフォーマンス向上）

### エージェントサービス (`travel-agent-service`)
- **CPU**: 2 vCPU
- **メモリ**: 4Gi
- **最小インスタンス**: 1（レスポンシブ対応）
- **最大インスタンス**: 15（AI処理負荷分散）
- **同時リクエスト数**: 100/インスタンス（AIタスクの特性を考慮）
- **タイムアウト**: 900秒（AIモデル推論時間確保）
- **実行環境**: gen2

## 開発環境 (dev ブランチ)

### メインアプリケーション (`izatabi-app-dev`)
- **CPU**: 1 vCPU
- **メモリ**: 2Gi
- **最小インスタンス**: 0（コスト最適化）
- **最大インスタンス**: 10（開発テスト対応）
- **同時リクエスト数**: 100/インスタンス
- **タイムアウト**: 600秒
- **実行環境**: gen2

### エージェントサービス (`travel-agent-service-dev`)
- **CPU**: 1 vCPU
- **メモリ**: 2Gi
- **最小インスタンス**: 0（コスト最適化）
- **最大インスタンス**: 10（開発テスト対応）
- **同時リクエスト数**: 50/インスタンス
- **タイムアウト**: 600秒
- **実行環境**: gen2

## 設定根拠

### リソース設定
- **2 vCPU / 4Gi (本番)**: AI推論タスクとWeb処理の並行実行に対応
- **1 vCPU / 2Gi (開発)**: 開発テスト用途でコスト効率を重視

### スケーリング設定
- **本番最大インスタンス数**: メインアプリ20、エージェント15で大規模同時利用に対応
- **開発最大インスタンス数**: 10で開発テストに十分な容量を確保
- **最小インスタンス数**: 本番は1-2でレスポンシブ対応、開発は0でコスト削減

### 同時リクエスト数
- **メインアプリ**: 200（Webリクエスト処理に最適化）
- **エージェント**: 50-100（AI処理の特性を考慮、リソース集約型タスク）

### タイムアウト設定
- **900秒 (本番)**: Gemini APIでの複雑な旅行プラン生成に対応
- **600秒 (開発)**: 開発テスト用途で適切なタイムアウト

## 期待される効果

1. **スケーラビリティ向上**: 最大20インスタンスで数百ユーザーの同時利用に対応
2. **レスポンス性能向上**: 最小インスタンス設定でコールドスタート削減
3. **AI処理安定性**: 十分なリソースとタイムアウトでGemini推論の安定実行
4. **コスト効率化**: 環境別設定で本番品質と開発効率を両立

## 監視・調整ポイント

- **CPU使用率**: 70%超過時のスケーリング動作を監視
- **メモリ使用率**: 4Gi設定での実際の消費量を確認
- **リクエスト待機時間**: 同時リクエスト数設定の適切性を評価
- **タイムアウト発生率**: AI処理時間の実績に基づく調整検討
